# Playlist Lab hosting

Status September 22, 2026: Docker image and private service tested; a dedicated remotely managed Tunnel has been created, with its token stored privately. The separate Cloudflare Access application, tunnel route and public URL verification remain pending. The current local server remains the live review interface until cutover. Do not distribute the proposed URL before the live checks below pass.

## Architecture

`https://music.hollow-court.com` will be a separate Cloudflare Access self-hosted application, not an added path on the game-admin application. Its allow policy starts with the existing host email; add invited reviewers' exact email addresses only when supplied by the host. Access email one-time PIN can use the existing team login method. Give this application its own audience (AUD). The existing `/host` and `/api/admin` policy and audience on `hollow-court.com` stay scoped to game administration.

Cloudflare Tunnel points the music hostname to `http://lab:8765` on the Compose network. Neither Compose service publishes a host port. The lab independently checks the Access JWT signature, issuer, audience, expiration and identity on every HTTP request. Guest votes, notes and optional listening scores are keyed to their signed email; the host's preexisting votes stay in the legacy feedback table. Guests cannot read the host event history or other reviewers' choices. The host can read guest votes and notes from `/api/reviewers`; this endpoint requires the host identity. Votes never modify Spotify automatically.

The Mac running Docker must stay awake and online for the public URL to work. The local server at `127.0.0.1:8765` uses the old local database and is *not* the shared hosted state. For future batch imports and enrichment after cutover, use `--state music/playlist-lab/.local/hosted` with `lab.py`, or `--state` with `enrich.py` and `youtube.py` as appropriate. Do not edit the same SQLite database from host commands while the container is running; stop the lab first, run the command, then restart it.

## One-time deployment

1. In Cloudflare Zero Trust, create a **self-hosted** Access application for the exact hostname `music.hollow-court.com`, with an Allow policy for the host email and any host-approved reviewer addresses. Copy its application AUD. Create this Access application *before* creating a public tunnel route. A separate application prevents reviewers from inheriting game admin rights.
2. Use the existing remotely managed Tunnel `october-grove-playlist-lab` and add a published application route for `music.hollow-court.com` → `http://lab:8765`. Enable the route's **Protect with Access** setting and select the new music Access application. The route also creates/uses a DNS record for this hostname. The tunnel token is already in ignored `.local/tunnel-token`; it is a bearer secret.
3. From this directory, copy `.env.example` to ignored `.env`, replace AUD and host email, and confirm `id -u`/`id -g` match `PLAYLIST_LAB_UID`/`PLAYLIST_LAB_GID`. Confirm ignored `.local/tunnel-token` has mode `0600`. Do not commit either file. Cloudflare Access credentials and the Spotify token remain private.
4. If `.local/hosted/library.sqlite3` does not exist, run `python3 bootstrap_hosted.py` to copy the existing local library and votes. The script refuses to replace an existing hosted database. Immediately before cutover, compare source and hosted vote counts; if local voting continued after the initial copy, reconcile those new host votes before asking people to use the hosted URL.
5. Run `docker compose config --quiet`, then `docker compose up -d --build`, then `docker compose ps` and `docker compose logs --tail=50 lab tunnel`. Do not put a real Access token or tunnel token in a shell history or logs. `docker compose down` stops the services; it leaves the private database in `.local/hosted`.

The `.env` values are application config, not substitutes for an Access policy. The lab fails closed without a valid signed token for the *music* application. The container connects outbound through the tunnel and has no published port. The existing local service remains available until cutover; stop it after the public review flow is proven and its latest host votes are present in hosted state.

## Live checks and operations

- With no Access session, the public URL should redirect to Access. Sign in as an allowed reviewer and confirm the 241-track library loads, a test vote saves, and reload preserves that reviewer's choice. A different reviewer should start unrated for that track. Verify the host still sees the original votes and can view the guest report at `/api/reviewers`.
- Sign in with an address outside the music allow policy and confirm it cannot reach the lab. Check that music reviewers cannot reach the game host guest book. Also confirm a direct request to the container without a signed JWT returns 401; the lab enforces this even if tunnel Access protection is accidentally removed.
- Back up `.local/hosted/library.sqlite3` with SQLite's backup API while the lab is running, or stop the lab and copy the file. Back up the ignored `.env` and tunnel token separately in a secure private store. A Git commit does not save votes.
- To review collaborators' decisions after sign-in as host, open `/api/reviewers` in the browser. It returns each guest's email, track, vote, note and update time. The local `export` command exports only the host's legacy view and events; it does not merge guest votes into Spotify actions. Decide which tracks to promote through normal host review.
