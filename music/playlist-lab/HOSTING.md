## Architecture

`https://music.hollow-court.com` is a separate Cloudflare Access self-hosted application, not an added path on the game-admin application. It reuses the existing host-only email policy. Add invited reviewers' exact email addresses only when supplied by the host; use a separate music reviewer policy, not the game-admin policy, when expanding access. Access email one-time PIN uses the existing team login method. This application has its own audience (AUD). The existing `/host` and `/api/admin` policy and audience on `hollow-court.com` remain scoped to game administration.

Cloudflare Tunnel points the music hostname to `http://lab:8765` on the Compose network. Neither Compose service publishes a host port. The lab independently checks the Access JWT signature, issuer, audience, expiration and identity on every HTTP request. Guest votes, notes and optional listening scores are keyed to their signed email; the host's preexisting votes stay in the legacy feedback table. Guests cannot read the host event history or other reviewers' choices. The host can read guest votes and notes from `/api/reviewers`; this endpoint requires the host identity. Votes never modify Spotify automatically.

The Mac running Docker must stay awake and online for the public URL to work. The local server at `127.0.0.1:8765` uses the old local database and is *not* the shared hosted state. For future batch imports and enrichment after cutover, use `--state music/playlist-lab/.local/hosted` with `lab.py`, or `--state` with `enrich.py` and `youtube.py` as appropriate. Do not edit the same SQLite database from host commands while the container is running; stop the lab first, run the command, then restart it.

It uses the existing host-only policy and a 12-hour session. Its application AUD is stored in ignored `.env`. Do not modify the reusable host policy to grant music reviewers game-admin access.
2. The remotely managed Tunnel `october-grove-playlist-lab` routes `music.hollow-court.com` to `http://lab:8765`, with **Protect with Access** requiring the music application audience. A proxied DNS record points the hostname to this Tunnel. The token lives in ignored `.local/tunnel-token` and is a bearer secret.
3. Ignored `.env` contains the public origin, Access team domain, music AUD, host email and matching `PLAYLIST_LAB_UID`/`PLAYLIST_LAB_GID`. If rebuilding on another Mac, use `.env.example` to recreate it privately; never commit it or the tunnel token.
4. The one-time `bootstrap_hosted.py` copy has already created `.local/hosted/library.sqlite3`. It refuses to replace an existing hosted database. Before retiring the old local server, compare source and hosted vote counts; if local voting continued after the initial copy, reconcile the new host votes.
5. From `music/playlist-lab`, run `docker compose config --quiet`, `docker compose up -d --build`, `docker compose ps`, and `docker compose logs --tail=50 lab tunnel` for recovery or updates. `docker compose down` stops services but preserves the hosted database.

The `.env` values are application config, not substitutes for an Access policy. The lab fails closed without a valid signed token for the *music* application. The container connects outbound through the tunnel and has no published port. The existing local service remains available until cutover; stop it after the public review flow is proven and its latest host votes are present in hosted state.

## Security boundary and review

A focused configuration and code review on September 22 found no Docker host-port binding for either Compose service. The lab listens on port 8765 **inside** the Compose network; `cloudflared` makes outbound connections to Cloudflare and forwards only the music hostname to it. The Tunnel route requires the music Access audience and returns 404 for other hostnames. Anonymous public requests reached the music Access login. The lab also verifies the Access JWT signature, team issuer, music audience, expiry and email on every request; writes additionally require the exact HTTPS Origin and a CSRF token. The page now denies framing and suppresses referrers. The game-admin application has a different audience and was not widened.

This is a targeted review, not an independent penetration test. A process on the Mac or a container joined to the Compose network can reach the lab's HTTP port, but it still needs a valid music JWT to read or write. The separate old local server on `127.0.0.1:8765` remains unauthenticated and loopback-only; it uses a different database. Cloudflare remains the identity issuer and policy enforcement point; a stolen valid Access token could be replayed until it expires. An unapproved identity and a second approved reviewer have not yet been tested end to end. Keep the tunnel token and hosted database private.
