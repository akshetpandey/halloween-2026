## Build pipeline

1. **Freeze approved recordings.** Read host bedroom Keeps from the authoritative Playlist Lab database, preserving exact Spotify URI/ISRC and vote timestamp. Exclude Cut, Maybe and unrated tracks; guest feedback remains advisory until the host approves. Refresh before each build so later Cuts invalidate the crate. No living-room approvals leak into this set.
2. **Acquire and bind exact files.** Use owned purchases or permitted artist/label downloads. Save source, original checksum and version verification. A radio edit and an extended mix are different preparations; do not substitute automatically. Spotify application downloads are not ordinary source audio. The [source/analysis research](research/local-track-analysis-2026-10-19.md) covers acquisition and model options.
3. **Analyze once per file hash.** Run actual-file beat/downbeat, key/confidence, loudness/true peak and structural analysis. The implemented audition analyzer uses librosa/NumPy/SciPy onset harmonics, RMS/lowband energy and chroma/texture similarity; all twelve chosen sources pass constant-grid mechanical checks. Downbeat and eight-bar phase remain provisional. Essentia and All-In-One remain uninstalled candidates for stronger recognition. Keep catalog ReccoBeats descriptors separate. Low-confidence grids and 87/174 BPM ambiguity need correction before editing. [All-In-One](https://github.com/mir-aidj/all-in-one) · [Essentia](https://essentia.upf.edu/tutorial_extractors_musicextractor.html) · [librosa recurrence/segmentation](https://librosa.org/doc/0.11.0/auto_examples/plot_segmentation.html)
4. **Choose shortened edits.** Generate a cut sheet keyed to original hash, with retained source ranges, phrase anchors, reasons and confidence. The agent accepts/revises those edits without per-cut host decisions. Shorten repeated 8/16/32-bar passages where the arrangement adds little; reduce empty lead-ins and prolonged breakdowns. Preserve the hook, a worthwhile build/drop and enough drums for the next blend. Repetition alone does not prove boredom. Review each splice in context and prefer a simpler exit over an uncertain aggressive cut.
5. **Create coherent chapters.** Plan roughly 60–90-minute projects within the [event energy arc](../playback-plan.md), rather than one huge interleaved five-genre project. Keep DnB in deliberate blocks and choose artist/texture variation before optimizing BPM/key. The agent owns the energy arc; catalog energy is only a hint. Reject extreme time stretching; a key match cannot rescue a poor musical pairing.
6. **Build and refine the REAPER timeline.** Generate Lua to import verified files, place retained ranges and set rate, gain, fade and EQ envelopes. Start with restrained phrase-length blends and bass handovers. Avoid two basslines or two lead vocals fighting. For DnB/4-to-the-floor boundaries use an intentionally designed reset, approved bridge recording or tested half/double-time join; no forced 128→174 beatmatch. Save the edit manifest and project so any change is reproducible. Agent checks every transition/splice and revises issues rather than sending a per-join approval queue to the host.
7. **Render and verify.** Render each chapter as one continuous lossless file, assemble the chapter boundaries into a continuous FLAC master, and produce an MP3 backup plus chapter files and a timestamped tracklist. Use offline REAPER rendering once the actual version's script/render route is proved. Measure final duration, clipping/true peaks, silence, cut/beat alignment and gains after all overlaps, rate changes and cuts. Those measurements support quality control; they do not establish subjective listening quality by themselves.
