| Option | Fit for this party | Automation boundary |
|---|---|---|
| **DJ.Studio Pro — recommended** | DJ-specific beat/key ordering, editable transitions and track structure; inspect the whole mix before export | Import our local M3U8 crate, generate a first draft, then refine it. ## Build pipeline

1. **Freeze approved recordings.** Read host bedroom Keeps from the authoritative Playlist Lab database, preserving exact Spotify URI/ISRC and vote timestamp. Exclude Cut, Maybe and unrated tracks; guest feedback remains advisory until the host approves. Refresh before each build so later Cuts invalidate the crate. No living-room approvals leak into this set.
2. **Acquire and bind exact files.** Use owned purchases or permitted artist/label downloads. Save source, original checksum and version verification. A radio edit and an extended mix are different preparations; do not substitute automatically. Spotify application downloads are not ordinary source audio. The [source/analysis research](research/local-track-analysis-2026-10-19.md) covers acquisition and model options.
3. **Analyze once per file hash.** Run actual-file beat/downbeat, key/confidence, loudness/true peak and structural analysis. Essentia plus All-In-One are candidates; librosa recurrence can flag repeated passages. Keep catalog ReccoBeats descriptors separate. Low-confidence grids and 87/174 BPM ambiguity need correction before editing. No model has been installed or benchmarked here. [All-In-One](https://github.com/mir-aidj/all-in-one) · [Essentia](https://essentia.upf.edu/tutorial_extractors_musicextractor.html) · [librosa recurrence/segmentation](https://librosa.org/doc/0.11.0/auto_examples/plot_segmentation.html)
4. **Propose shortened edits.** Generate a cut sheet keyed to original hash, with retained source ranges, phrase anchors, reasons and confidence. Shorten repeated 8/16/32-bar passages where the arrangement adds little; reduce empty lead-ins and prolonged breakdowns. Preserve the hook, a worthwhile build/drop and enough drums for the next blend. Repetition alone does not prove boredom. Audition each proposed splice with surrounding context before accepting it.
5. **Create coherent chapters.** Plan roughly 60–90-minute projects within the [event energy arc](../playback-plan.md), rather than one huge interleaved five-genre project. Keep DnB in deliberate blocks and choose artist/texture variation before optimizing BPM/key. Harmonize explicitly does not optimize subjective energy. Reject extreme time stretching; a key match cannot rescue a poor musical pairing.
6. **Draft and refine transitions.** Start with restrained phrase-length blends, bass handovers and selective filtering. Avoid two basslines or two lead vocals fighting. For DnB/4-to-the-floor boundaries use an intentionally designed reset, a suitable bridge recording, or a tested half/double-time join; no forced 128→174 beatmatch. Lock good joins before reordering the rest. Audition every transition and interior splice, not only flagged harmonic mismatches.
7. **Render and verify.** Export each chapter as one continuous lossless file, assemble the chapter boundaries into a continuous FLAC master, and produce an MP3 backup plus chapter files and a timestamped tracklist. Do not use per-track split exports as if they were a guaranteed reconstruction of the mix: the vendor documents changed transitions with that mode. Measure final duration after all overlaps, rate changes and cuts.

### How much can code actually do?

The [implemented preparation tool](premix/README.md) already exports the approved pool and a validated local-file M3U8 without touching the review database. DJ.Studio officially imports M3U/M3U8 in playlist order. Its “automation” refers to audio parameter curves, not a Python automation API. [Import documentation](https://help.dj.studio/en/articles/9561495-import-a-playlist-file-m3u-or-m3u8-into-dj-studio)

The remaining analysis, sequencing and edit generation are **planned**, not implemented. For automatic interior cuts without relying on private DJ.Studio internals, Python can render accepted retained ranges into **derived lossless edits**, then supply those files in a new M3U8. Keep original/derived hashes and the source-range map so every edit can be undone. DJ.Studio handles the resulting transitions. Its own manual supports non-destructive interior cuts for corrections. [Editing controls](https://help.dj.studio/en/articles/8207056-editing-audio-files-cut-copy-paste)

If fully automatic timeline rebuilding and rendering become essential, use the same edit manifest to generate a **REAPER Lua script** through its supported API. That route can automate source offsets, fades, tempo/pitch handling and EQ, while leaving an inspectable project. Do not reverse-engineer `.djs` projects or drive thousands of mouse clicks. FFmpeg can execute trims/fades, measure loudness and convert delivery files; it does not determine good musical phrasing. [FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html)

## Duration and playback

Prepare **at least nine hours of distinct usable finished audio after edits/transitions**. The proposed event window, `2026-10-31T21:30:00-04:00` through `2026-11-01T04:00:00-05:00`, is 7.5 elapsed hours; the remaining prepared material is reserve, not a later closing. Put the programmed closing at the event stop and keep reserve clearly indexed. Playback/stop control and the real FLX4/speaker route still need rehearsal; no camera or live selection service is needed.

Do not assume one nine-hour DJ.Studio project/export works. The default 60-track cap can be disabled, but no maximum-hour guarantee was established. Manageable chapter renders avoid making the entire set depend on one large project. Ordinary RIFF WAV is also unsuitable for a nine-hour stereo PCM16/44.1 kHz master: audio alone is about **5.72 GB**, beyond its 4 GB boundary. Use lossless chapter WAVs and a FLAC master, or a verified RF64/W64 workflow. Test seeking and the final minutes in the chosen player. [Track cap/settings](https://help.dj.studio/en/articles/8105773-settings-menu) · [WAV/RF64](https://ffmpeg.org/ffmpeg-formats.html#wav)
